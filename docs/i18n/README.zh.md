# 双语文档

[English](README.md) | 中文

## 配对约定

英文与简体中文具有同等效力，任一语言都可以先写，审阅时确保两种语言表达相同的事实和验证边界。每篇面向读者的 Markdown 页面由同目录的 `name.md`、`name.zh.md` 和 `name.i18n.yaml` 三个文件组成，不使用语言目录或交错排布的双语正文。

H1 标题后紧接语言切换链接，英文页链接到中文，中文页返回英文。内部链接指向文档配对中与读者相同的语言；标题层级和顺序、列表结构、表格维度与链接目标相互对应。代码块逐字节一致，包括语言标记。

名为 `AGENTS.md` 或 `CLAUDE.md` 的指令文件，以及本身为双语的[术语表](terminology.md)，不参与配对。其他 Markdown 页面自动纳入检查，包括未来新增的研究和决策记录。译文或同步记录缺少对应英文文件时，检查报错。

## 编辑与验证

阅读术语表，更新两个页面并审阅语义。仅为已经核对过译文的配对更新记录：

```bash
python3 -I scripts/check_docs.py --record README.md docs/development.md
```

运行全库检查：

```bash
python3 -I scripts/check_docs.py
```

检查器只使用 Python 标准库。每份记录按英文标题路径划分章节，分别保存两种语言 SHA-256 哈希的前 16 位十六进制字符。本仓库的简化实现对完整章节计算哈希，包含代码块，但排除语言切换行。这是借鉴上游的本地格式，不能直接替代上游检查器。生成记录前先验证结构，不自动翻译正文。

CI 拒绝缺失配对、过期记录、结构不匹配、失效的本地文件链接、内部链接语言错误、代码围栏格式错误、行尾空格、非 LF 换行和缺少结尾换行。支持的 Markdown 子集包含 ATX 标题、简单行内链接、围栏代码块、列表与管道表格。链接使用普通标签，可附带双引号标题；不支持的链接形式、引用式链接和原始 HTML 链接会报错。应明确链接到对应语言的 README，不链接到其目录。本地片段锚点不校验，也不跨语言比较；远端 URL 精确比较，但不发送请求。

通过 Git 发现已跟踪文件和未忽略的未跟踪文件，构建产物及本地工具目录仅在仓库根目录排除。`docs/build/` 等文档路径仍在检查范围内。没有 Git 仓库的检查器临时测试使用文件系统发现，采用相同的根目录排除规则。

## 审阅职责

哈希只能证明这些具体内容曾一起生成记录，不能证明语义相同。审阅负责技术准确性、语言自然度、术语，以及建议和已验证行为的区分。不要仅为消除 CI 报错而刷新记录；合并冲突时，先解决两份正文，再更新记录。

章节变更时，只对译文做必要修改。需要固定译法时，在共用术语表中补充条目。代码标识符、协议方法、路径、版本字符串和精确命令保持不变。
