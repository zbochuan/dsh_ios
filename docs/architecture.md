# Application architecture

English | [中文](architecture.zh.md)

## Current implementation

DSH is an independent Swift 6 / SwiftUI client targeting iOS 17 and later. Compact layouts use a conversation navigation stack with history in a sheet; regular layouts use a history sidebar and conversation detail. Computers and Settings are secondary destinations. The checked-in [Xcode project](../DSH.xcodeproj/project.pbxproj) builds the application and its UI tests; the local [DSHCore package](../Packages/DSHCore/Package.swift) owns portable state and protocol code. No third-party Swift package dependency is required.

| Area | Implemented behavior | Verification boundary |
|---|---|---|
| Native interface | Compact entry, searchable history, conversation and composer, collapsible reasoning/activity, contextual approval sheet, computers and appearance settings | Replies and approvals are local demonstrations. Source implementation does not establish native visual or accessibility acceptance. |
| Conversation state | Incremental preset text, stop, per-conversation drafts, exit/resume within a launch, one-time approval consumption and invalidation on background | In-memory demo state only; no real Harness session reducer or durable history yet. |
| Remote Server | HTTPS login, iOS device registration, credential refresh, Host discovery and descriptor API | Request-schema tests; no service account or live Host used. |
| Credentials | X25519 device identity and device tokens in non-synchronizing, device-only Keychain storage, scoped to normalized Server origin | Passwords and registration tokens stay transient. Keychain storage and connection recovery still require physical-device validation. |
| Encryption | Noise IK initiator and ordered secure fragmentation | Golden-vector and local responder tests; not an independent cryptographic audit or real-Host interoperability. |
| Remote session | Not wired into the interface | Control/Relay carrier, Host key trust, RPC, session streams and real approvals remain to implement. |

The conversation title carries one tappable Local demo label with the preset-response, no-execution and in-memory-storage explanation. Approval outcomes describe a local choice. Computer discovery explains that it does not establish a secure session, and exposes no enabled remote-chat action. No model API key is collected. Remote account information is sent only after the user supplies a Server and submits login. Production REST sessions reject redirects, avoid cookies and caches, and accept HTTPS origins only. UserDefaults stores the committed Server address, appearance preference and login-required recovery flag; no password or device token is written there.

## Source ownership

- [AppStore](../App/AppStore.swift) owns local demonstration selection, drafts, task cancellation and per-conversation generation tasks. Entry opens a blank conversation; history retains the examples. New conversation reuses an untouched blank when available. Leaving the demo preserves this launch's history and drafts. Leaving or backgrounding cancels simulated generation and invalidates demo approvals; it never sends a Host command.
- [ConnectionStore](../App/ConnectionStore.swift) coordinates explicit login, Keychain restore, credential refresh, discovery and local sign-out. Form edits stay separate from the committed Server. Credential operations serialize; rejection of device authorization clears signed-in state, while a discovery network failure preserves successful authentication. Account-login failure before registration preserves existing device credentials and signed-in state; this behavior is source-reviewed, not verified with a live account. Restore can recover signed-in state for the committed Server, but `accountName` is only set during explicit login and is neither persisted nor reloaded; the account-name row is therefore absent after a fresh launch restores credentials. Device tokens and identity keys remain in Keychain. Uncertain token replacement requires login. Recovery offers restore retry, local sign-out and confirmed removal only for an unreadable identity. Sign-out clears local tokens but does not revoke the Server-side device.
- [Conversation](../Packages/DSHCore/Sources/DSHCore/Conversation.swift) owns demo messages, generation phase, drafts and pending approvals. Approval detail shows the example computer, full workspace, command and scope. Closing leaves a valid request unanswered; resolution checks its identifier and waiting phase, consumes it once and appends a local result. Invalidation retains drafts and adds an explanation.
- [RemoteServerAPI](../Packages/DSHCore/Sources/DSHCore/RemoteServerAPI.swift) implements pinned Server wire shapes. [DeviceIdentity](../Packages/DSHCore/Sources/DSHCore/DeviceIdentity.swift) and [CredentialStore](../Packages/DSHCore/Sources/DSHCore/CredentialStore.swift) isolate identity and persistence.
- [NoiseIK](../Packages/DSHCore/Sources/DSHCore/NoiseIK.swift) and [SecureChannel](../Packages/DSHCore/Sources/DSHCore/SecureChannel.swift) implement the initiator and framing independently from network I/O. The future carrier must serialize an entire encrypt-and-send operation, including all fragments; actor isolation alone cannot order later socket sends.

## Interface and design

[Mobile product design](product-design.md) owns the official Claude/ChatGPT screenshot evidence, revised interaction direction and acceptance criteria. The implementation removes the promotional hero and feature cards, gives assistant prose an unboxed reading surface, uses neutral user bubbles and retains one composer. The first interface is Simplified Chinese. System fonts, semantic text sizes, minimum 44-point primary targets and native navigation/sheets provide the foundation. Physical hit testing, full Dynamic Type layout, VoiceOver and interaction quality still need native review. [Development](development.md) distinguishes the completed simulator assertions and device launch from those remaining checks.

[DSHTheme](../App/Design/DSHTheme.swift) maps the official [Harness design tokens](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/client/ui-theme/src/styles/design-platform.css) into opaque neutral surfaces with blue reserved for available actions and selection. The base blue is `#4176E6` in light appearance and `#5686FE` in dark appearance; text actions use separate contrast-oriented shades. The reading column is capped at 680 points. Appearance follows the system or an explicit preference. [Upstream brand guidance](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/BRAND_GUIDELINES.md) informs the independent DSH naming.

Press feedback immediately changes opacity to `0.72` and, for compact controls, scale to `0.97`; release uses a spring with response `0.3` and damping fraction `1`. A stationary minimum hit region surrounds the visual transform. Wide rows use opacity only. Reduce Motion removes scale and animation while retaining immediate opacity feedback. Explicit return-to-latest uses a spring with response `0.35` and damping fraction `1`, or immediate positioning with Reduce Motion. These describe source parameters, not measured physical interaction quality.

Messages remain selectable and copyable. The composer stays in a safe-area inset, reasoning and activity default to collapsed, and incoming text does not animate the entire layout. History scrolling can leave the latest position; a return-to-latest action appears. Automatic streaming scroll pauses during that explicit return animation. Native scroll and sheet gestures remain intact. Rich Markdown, syntax-highlighted code, attachments and file previews are not implemented yet.

## Next integration boundary

Connect to the fixed Remote revision documented in [research](research/ds-harness-remote-ios.md), negotiate capabilities, establish the Control/Relay carrier, verify and pin the Host public key, then complete Noise before sending any RPC. The app must not replace this with plaintext RPC or model API requests. Implement `harness.transport.describe` and the unary/stream gateway with subscription registration before open, explicit timeouts, pending-call teardown and approval invalidation.

A real session must keep durable history separate from live assistant attempts, replace its baseline after reconnect, and never automatically replay an unconfirmed mutation. Accepted work continues on the computer; closing or backgrounding iOS is not a cancellation request. Real-Host versions, stream completion, stop, approvals, transfers and reconnect evidence must be recorded before describing that path as supported. [Development](development.md) owns build and release validation.
